# Exploración ampliada del sistema visual de Relevo

Esta carpeta reúne una biblioteca de sesenta piezas vigentes para estudiar cómo el lenguaje de Relevo puede trasladarse entre interfaz Android, memoria, carteles, recursos transparentes, fondos y situaciones físicas. Cada pieza fue generada de manera independiente. Las hojas de contacto sirven para revisar familias completas y no se contabilizan dentro de las sesenta piezas.

## Principio común

El sistema representa una intención que parte desde un campo de origen, atraviesa un vínculo y vuelve a hacerse perceptible mediante una señal situada. La matriz de puntos cambia de densidad y organización; no representa porcentaje, rendimiento ni avance obligatorio. El rojo se reserva para la señal situada o para una decisión de diseño que exige atención puntual.

El modo oscuro es la dirección vigente para la aplicación. El modo claro se desarrolla principalmente para la memoria, carteles, presentaciones y comparaciones de contraste. Esta distinción evita convertir ambos modos en simples inversiones cromáticas.

## Cómo leer la colección

- `00_contacto-*.png` permite comparar una familia completa; no es una pieza final.
- Los archivos terminados en `exploratorio` conservan una idea útil, pero requieren corrección antes de implementarse.
- Los mockups editoriales proponen retícula y jerarquía. Sus cifras, citas o referencias internas son contenido ilustrativo y nunca deben trasladarse a la memoria sin verificación.
- Las pantallas son objetivos visuales para reconstrucción. No son especificaciones Android ni reemplazan el flujo y las microcopias vigentes.
- Las escenas físicas comparan presencia, escala y ubicación. No fijan todavía la forma, material ni sistema productivo del dispositivo.

## Criterios de selección

Una pieza puede avanzar si mantiene una jerarquía legible, distingue información de acción, conserva el rojo como señal excepcional, deja espacio para contenido real y puede reconstruirse sin depender de errores del generador. Si falla una regla estructural, se mueve a `99_descartados` y se registra el motivo.

## Registro de cambios

### 2026-09-01 — Ampliación a sesenta piezas

- **Cambio:** la colección pasó de doce a sesenta piezas vigentes, organizadas en seis familias de diez, más hojas de contacto y cuatro descartes documentados.
- **Versión anterior:** existían cinco familias incompletas, dos pantallas Android, dos aplicaciones editoriales, un cartel, cuatro módulos y dos fondos; no había una familia de contexto físico.
- **Motivo:** obtener amplitud suficiente para comparar alternativas sin confundir cantidad con aprobación y sostener decisiones posteriores con una biblioteca ordenada.
- **Alcance:** las piezas fijan una dirección visual y un campo de alternativas; todavía requieren reconstrucción editable, pruebas de legibilidad y validación situada.

### 2026-08-31 — Creación de la colección

- **Cambio:** se incorporaron doce piezas independientes en cinco familias visuales y un archivo de descarte.
- **Versión anterior:** el sistema v4 reunía pantallas y láminas de dirección, pero no una colección comparativa.
- **Motivo:** ampliar la exploración sin perder la semántica de origen, vínculo y señal situada.
